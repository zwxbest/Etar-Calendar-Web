# Etar 日历网页端

Vue 3 + Vite 实现的 Etar 日历网页端，复刻 App 的**天视图**：

- 时间网格 + 12 单位宽度任务块（1 单位 = 2.5 分钟），配色与 App 一致
  （高优先级混紫、弹性任务混白）
- 底部常驻创建栏（优先级 + 输入框 + 2/5/10/15/20/25/补满按钮），
  目标时段是当天第一个任务时默认选中「补满」
- 右键任务 = 手机端长按菜单（编辑/移动/弹性/优先级/调整时长/补满/删除），双击 = 删除
- 单击任务选中，再单击空白时段把任务移动过去；单击空白时段（未选中时）设为创建目标
- 顶部 ← → 切换昨天/明天，右上角显示连接状态（连接中/已连通/离线，有待同步改动时
  追加"· N 条待同步"，发送中显示"同步中…"）
- **离线可用**：手机息屏/锁屏断连期间照常增删改日程——改动先入 localStorage 的待同步队列
  （`etar_pending`），当天基准缓存在 `etar_events_<yyyy-MM-dd>`，重连后攒成一批
  （`batch` 消息，按 id 整批幂等，见 `MQTT信令协议.md` §10）一次同步到手机，再 fetch 逐天对账；
  手机本地库仍是**唯一权威数据源**，网页端只是"本地操作层 + 缓存"（在途批次号持久化在
  `etar_inflight`）。本地渲染永远是"基准 + 待同步队列"推导出来的，被手机校验拒绝的改动
  会随下一次 fetch 自动回退。localStorage 不可用时降级为纯内存（一次性 toast 提示），
  另有 7 天前的基准自动清理
- 配对：首次打开输入 6 位配对码连接手机；配对成功后 localStorage 记住手机
  peerId，下次打开自动重连。信令地址内置（`src/lib/store.js` 的 `SIGNAL_URLS`），
  弹窗里无需配置

## 底层

- 数据通道：MQTT（局域网自建 EMQX，`192.168.96.58`）。网页只连 broker，
  日程数据经加密信封（`type="data"`）收发，主题划分与 join/here/leave/data 报文见
  `MQTT信令协议.md`；原 `../signaling/` Worker 已作废
- 信令地址：网页 `ws://192.168.96.58:8083/mqtt`，安卓 `tcp://192.168.96.58:1883`；
  断线后两端都按**固定 1 秒**间隔重连（不做指数退避）
- 依赖 `mqtt`（mqtt.js），首次拉代码需 `npm install`

## 开发/构建

```bash
npm install
npm run dev      # 本地开发 http://localhost:5173
npm run build    # 产物在 dist/，任意静态服务器托管即可
```

注意：浏览器要求安全上下文（https 或 localhost）才能使用 WebRTC。

## 协议

见 `src/lib/sync.js` 头部注释与 `MQTT信令协议.md`（§9 数据通道、§10 批量改动 batch）；
日程数据以安卓本地库为唯一数据源，网页端的离线队列与缓存见 `src/lib/cache.js`。
